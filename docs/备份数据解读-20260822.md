## 1. LXY.JBR（竞赛作业文件，16 行）

```
P001 = 3,1,0,0,0,0,0, -268.166,56.1283,290.13, 3.10135,0.386687,-3.12376, 0
NOP
MOVJ P001 VJ = 10 % PL = 0 ACC = 10 DEC = 10 0
END
```

- 点位结构（14 元）按位置变量参数：**坐标类型 3,1 = 用户坐标系1**；左右手 0；运行手=0；
  XYZ=(-268.166, 56.128, 290.13) mm（**用户1 系**）；**ABC=弧度制存储**
  （3.10135 rad≈177.68°，0.386687 rad≈22.16°，-3.12376 rad≈-179.00°）；外部轴 0。
- 指令只有 1 条 MOVJ（10% 速、PL=0、ACC/DEC=10）。**目前没有任何 DOUT/WAIT 指令**——
  握手指令需新增（语法见 §6）。
- 结论：文件格式＝**任何坐标一律弧度存储**（与 isDeg 无关），这点与 0x2A03 的
  `pos=弧度 / posDeg=度` 完全一致。

### 4.1 ❗本节最大的漏看：`RemoteIO[0].posReset`（事后补记，2026-08-22）

> 本文当时逐个文件读了这份备份，**却只看了 `global.json` 的 `/operateParam` 一段**，
> 没有往下翻到 `RemoteIO`。真正的根因就在那里

> `SystemBackup08-22-22-13/` 里字段完全一致，可交叉核对）：

```

```

- `safeEnable=true` 打开了"运动前必须在复位点附近"的安全闸门；但逐轴容差
  `deviation` 是 **null**，闸门拿不到比较基准，于是**恒判不通过**。
- 后果：**远程模式**下任何走 `startRobotJobTask(..., safepos=1, call=moveToPos)`
  入口的指令（0x3003 / 0x3007 / 0x3002 / 0x4501 / 0x4502 全在此列）
  一律被拒，控制器日志固定打印"机器人1不在安全位置附近"——
  实测机器人**精确停在复位点、逐轴只差 1e-5°** 也照拒。
- 更狠的是拒绝后的处理链：`stop → JobClear → 脉冲使能=0 → Deadan_End → PowerOff`，
  即**每被拒绝一次就把伺服下电一次**。这解释了现场"一发运动指令就掉使能"的全部现象，
  与"指令不可达/参数非法"毫无关系。
- 对照实验：**示教模式**下同一批指令 40+ 次全部正常执行，零例外；远程模式 15 次全拒。
- 注意 3x101（复位点判定）**读到 1 也没用**：它与 ioControl 的闸门是两条不同代码路径，
  3x101=1 时闸门照样拒绝。
- 证据：`docs/现场备份-20260822/根因证据-控制器日志摘录.txt`、
  `docs/现场备份-20260822/SystemBackup08-22-22-13/configFile-21.05.23-4.1.1-202608222213/global.json`。

**教训（给后来的 agent）**：读备份时不要只 grep `/operateParam`。

## 6. LXY 握手指令的官方语法（本地手册 18.6/15.2/15.6）

- 全局变量：GBxxx(布尔)/GIxxx(整数)/GDxxx(实数)，程序内可 `GI001=1` 或 `SET GI001`；
- **等待：`WAIT GI001 == 1 T=2 F=1 Return=GB001`**（T=超时秒，不填则死等；F=滤波）；
- **输出：`DOUT OGH#(DOUT)15 T=1 1`**（例：DOUT1-1 组，端口 15，T=时间，末尾=错误停止处理）；
- 读取组：`DIN IGH#(1)`（端口值存入 GI001）；`READ_DOUT GI001 OGH#(1)`；
- 运动等待：`WAIT_POS`（SPEED/POS + ACCURACY + MINTIME/MAXTIME）。
- 所以 PC↔LXY 双向握手**不需要 DIN 硬件**：
  - LXY→PC：`DOUT ...13 T=0 0`（状态位）＋ PC 读 0x3602/0x3603（已验证）或 Modbus 4x801；
  - PC→LXY：Modbus **4x501+0 (=GI001)** 写值 + LXY `WAIT GI001 == 1 ...`；
  - 气阀：指令 `DOUT OGH#(DOUT)15/16`，端口 15/16 与 0x3601 一致（(1,0)关 ∅(0,1)开）。

  > **① 0x45xx 不是"真死"，是本文自己发漏了字段。**
  > 0x4501/0x4502 **必须带 `acc` 和 `dec`**，控制器的解析顺序是

### 9.1 现在代码里的正确做法（应以此为准）

- 运动前必须 **0x2002 查状态**，`!=3` 就 **0x2311** 上使能，且**每段运动都要重查**
  （每被拒绝一次就掉一次电，状态随时会变）。
- 示教模式下 0x2311 上使能后 `status=3` 会**一直保持，不需要按 deadman**；
  0x2301 deadman 是示教器按键通道，上位机发无效（恒回 `deadman:0`）。
- 运动后必须等 **0x3D03 `status=2`** 才算真的动了（`_await_motion_ack`）；
  **"位姿不变"绝不能当成功**。
- 报警帧的真实文本在 **0x2B03 的 `data` 键**（不是 `message`）。
- 下发前三道闸门：位移 **≤400mm**、**|A/B/C| ≤7 rad**（挡"度当弧度"）、姿态变化 **≤20°**。
- **coord=3 是用户坐标系**（本机实测，整条流水线以用户坐标系1 为准）。
- 夹爪 **0x3601 走另一条码路**，不受使能与闸门影响 ——
  **"夹爪能动"推不出"机器人能动"**，本文当时正是被这一点误导过。
