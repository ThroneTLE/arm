## 1. 【必做】工具坐标系：切还是不切

当前配置对应**默认法兰**：`tcp_from_grasp` 平移 110mm，含义是"TCP 在抓取点上方
110mm"。计划把工具坐标系标定成**工具手1**（TCP = 夹爪尖端）。

> ⚠️ **切换工具坐标系会让现有手眼矩阵失效。** 视觉链路是
> `user1_from_object = user1_from_tcp @ tcp_from_camera @ camera_from_object`。
> `tcp_from_camera` 是按**法兰**标定的；一旦 TCP 移到尖端，
> `user1_from_tcp` 的参考点变了而手眼没变，**所有物体坐标整体平移约 110mm**。
> 已用数值验证：不补偿正好偏 110.0mm，补偿后误差 0.000mm。

### 方案 A（推荐，改动最小）：不切，保持法兰

什么都不用做。现有手眼与 110mm 原样匹配，今天验证过的定位精度直接可用。
只需跑一次确认：

```bash
python -m competition_pipeline.scripts.calibrate_fingertip --write
```

指尖触桌读数应 **≈110mm**。若确实如此，说明配置自洽，直接进第 2 步。

### 方案 B：切到工具手1（**机器人全程不许移动**）

```bash
# 1) 保持当前姿态，工具仍是法兰
python -m competition_pipeline.scripts.retarget_tool_frame --capture-before

# 2) 示教器上完成工具手1 标定并切换为工具1 —— 不要移动机器人

# 3) 再读一次
python -m competition_pipeline.scripts.retarget_tool_frame --capture-after
python -m competition_pipeline.scripts.retarget_tool_frame --show      # 平移量应≈夹爪长度
python -m competition_pipeline.scripts.retarget_tool_frame --apply     # 自动补偿+备份
```

`--apply` 会同时把手眼矩阵补偿到工具1、把 `tcp_from_grasp` 的 Z 改成 0、
把 `tcp_to_fingertip_mm` 置 0，原配置备份到 `config/backups/`。

**必做验证**：把一个已知物体放在用户系原点识别一次，应得 `X≈0 Y≈0 Z≈物体高度`。
偏了立刻用备份回滚。

## 3. 单罐第一档 · 先 dry-run 再执行

```bash
./tool/visual_grasp_pipeline/run_oak_vision_node.sh          # 默认 dry-run
```

**⚠️ 必须从主仓这个路径启动。** 脚本用自身位置推 `PROJECT_ROOT`，从
`tool/arm_project_20260822/arm/...` 启动会走那份**没有今天全部修复**的旧副本。

流程：识别 → 看结果框里的抓取高度说明 → 用尺子量一下罐子实际位置对比 → 再执行。

结果框会打印这样一行，**执行前先看它**：

```
抓取高度规则：顶点与中心的中点｜物体高 115.0mm 顶面 115.0mm｜伸进夹爪 28.8mm（腔体 80mm）
夹持宽度 66.0mm
```

判断标准：

| 看什么 | 正常 | 不正常说明 |
|---|---|---|
| 物体高 | 与实物相符（易拉罐约 115–133mm） | CAD 缩放或位姿错了 |
| 顶面 | ≈ 物体高（罐子坐在桌面上） | 位姿的 Z 错了 |
| 伸进夹爪 | ≈ 物体高/4，且 < 65mm | 超了会被自动抬高并提示 |
| 夹持宽度 | 与实物直径相符 | 认错物体了 |

确认无误后加 `--enable-robot-motion` 重启，UI 里还会再确认一次。

## 出问题时的三个最可能原因

### A. 机械臂完全不动，但夹爪照常开合

复位点安全闸门在**远程模式**下拒绝每一条运动指令，并且**每拒绝一次就把伺服下电
一次**；而夹爪走 `0x3601` DOUT，是另一条码路，所以照常工作。

→ **切回示教模式**（实测示教模式下 40+ 条 MOVL 全部成功，远程模式 15 次全拒）。

详见 `docs/纳博特C1102-现场真相-必读.md`。

### B. 提示"伺服未能进入运行态"

安全闸门刚把伺服打掉了。现在每条运动前都会自动重新使能并校验，报错说明重新使能
也失败了 —— 检查示教器是否有未清报警、是否还在远程模式。

### C. 抓取被拒绝，提示"机械限制不是软件问题"

物体比夹爪可用张开还宽。当前配置 `jaw_max_open_mm: 85`（**目测值，未实测**）。
如果你们量出来更大，改 `competition.yaml` 的 `gripper_geometry.jaw_max_open_mm`。
苹果实测 75mm 是全场最宽的物体。
